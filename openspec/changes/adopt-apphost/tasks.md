## 2b. Registration-name displacement guards (BLOCKING — see proposal §"Binding adoption hazard")

`Bootstrap::register()` `registerService()`s LarpingApp's **own** FQCNs and points them at the
generics, unconditionally and with no `class_exists()` guard. Last registration wins, so
anything the app registers *before* the call is lost and anything registered *after* it wins.
None of these tasks is optional; each one is a live HTTP 500 or a silent security regression.

- [ ] 2b.1 **H1 — `SetupController` (ADR-042 setup wizard) must not break.** `lib/Controller/SetupController.php` is KEPT by this change and type-hints `private readonly SettingsService $settingsService`; `AppHostSettingsService` does **not** extend `OCA\LarpingApp\Service\SettingsService`, so after displacement the container injects the wrong type and PHP throws a `TypeError` → HTTP 500 on `GET /api/setup/status`, `POST /api/setup/config`, `POST /api/setup/action/{actionId}`. Pick ONE and record which: (i) re-register `OCA\LarpingApp\Controller\SetupController` **after** `Bootstrap::register()` with an explicit factory that also re-registers a concrete `OCA\LarpingApp\Service\SettingsService`, doriath-style; or (ii) retype `SetupController` (and any other kept consumer) against the AppHost service so the displaced binding is the *intended* one. Prove it by calling all three routes on a live instance and asserting non-500 — a passing unit test does not count, it mocks the service and never resolves the container
- [ ] 2b.2 **H2 — no route may name a method the generic does not have.** Enumerate every route in the post-adoption `appinfo/routes.php` whose `name` prefix is `dashboard`, `settings` or `preferences`, and assert the method part exists on the corresponding generic (`GenericDashboardController`: `page`, `catchAll`; `GenericSettingsController`: `index`, `create`, `update`, `load`; `GenericPreferencesController`: `getPreference`, `setPreference`). `settings#reimport` fails this check today — fix per task 2.2. Re-run gate-14 (route-reachability) after the rewrite
- [ ] 2b.3 **H3 — resolve the three info.xml-referenced stubs through the real container.** After the rewrite, assert `\OC::$server->get(OCA\LarpingApp\Repair\InitializeRegister::class)`, `…\Settings\LarpingAppAdmin::class` and `…\Sections\LarpingAppAdmin::class` each return an instance without throwing `QueryException`. A bare `extends Generic… {}` stub does NOT resolve (see task 2.4). This is what breaks `occ app:enable larpingapp` and the admin Settings page
- [ ] 2b.4 **H4 — `Bootstrap::register()` must not be able to kill LarpingApp's own registrations.** Apps register alphabetically, so `larpingapp` registers before `openregister` and the AppHost class is not yet autoloadable; an unguarded call throws `\Error` and aborts the entire `Application::register()`, silently dropping `CharacterRequirementListener` — the server-authoritative skill-requirement / XP-budget enforcement on character writes. Copy doriath's guard verbatim: `if (class_exists(Bootstrap::class) === false)` → `include_once __DIR__.'/../../../openregister/vendor/autoload.php'`, then `try { Bootstrap::register(...); } catch (\Throwable) { }`, and register `CharacterRequirementListener` (and the OR event listeners) **after** the try/catch. Prove the listener still fires by writing a character that violates a skill requirement on an instance with the AppHost path active and asserting the write is rejected — "no error in the log" is not evidence, this failure mode logs nothing
- [ ] 2b.5 **Displacement inventory sign-off.** For each name in the proposal's displacement table, tick exactly one of: *deleted* (concrete gone, generic is the intended implementation) or *overridden* (concrete re-registered after `Bootstrap::register()`). Grep the whole app for consumers of each displaced FQCN before ticking *deleted* — `OCA\LarpingApp\Service\SettingsService` currently has three non-test consumers (`SettingsController`, `SetupController`, `Repair\InitializeRegister`), only two of which this change touches
